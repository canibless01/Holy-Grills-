# Database trigger execution grants — 13 November 2026

Removed unnecessary PUBLIC/anon/authenticated EXECUTE from seven public RETURNS trigger helpers: review insert/protected columns, squad insert/protected columns, share insert, notification protected columns and leaderboard protected columns. Retained service execution and all attached trigger definitions. These were unnecessary RPC grants, not seven independently proven exploits: PostgreSQL trigger functions cannot be invoked as ordinary functions. No RLS predicates, customer aggregate reads, staff reports or table privileges were removed.

Applied migration: `20261113090014_restrict_client_trigger_function_execution.sql`. No new table, column, policy or trigger. Existing public helper predicates must remain executable for their RLS policies; blanket revocation would break customer/staff reads.

Live production BEGIN/ROLLBACK passed after migration: fresh actual authenticated student review insert normalizes reward/flag fields; review staff-only flag writes denied; squad inserts normalize reward/referral fields and reject forged share updates; share insertion enforces current WAT date; notification read receipts work while message edits fail; student leaderboard writes affect no rows; campus admin review moderation works, foreign-campus moderation fails and super-admin moderation works; public menu rating aggregation and original HP balances are preserved. Verified all seven original triggers remain enabled and client EXECUTE is denied. No genuine data or provider message was used. A separate read found zero public tables with RLS disabled.

Security advisors now show anon-definer warnings **13 → 6**, authenticated-definer warnings **22 → 15**. Remaining categories: two intentionally backend-only RLS/no-policy tables (`email_send_counters`, `newsletter_deliveries`), public pg_net extension placement, intentional predicate/aggregate/admin-report definer exposure requiring dependency-aware review, and Auth leaked-password protection configuration. This is not a statement that all remaining warnings are exploitable or that the entire historical database audit is complete.

An earlier temporary-table/GRANT test hit tool approval expiry twice and was abandoned. The successful test uses existing production tables and only fresh transaction-scoped fixtures; it adds no temporary grants.
