# Select rewards before choosing a location — 13 November 2026

Checkout now discovers the signed-in customer's owned delivery and food-HP rewards as the page loads. The Rewards box displays the count and opens usable choices without requiring a delivery location, cart quote or return visit. Delivery offers display their percentage and cap, and food offers display their multiplier. A chosen reward remains selected as the user picks or changes a location; the existing authoritative quote calculates the exact saving and total.

The authenticated, private/no-store `GET /orders/reward-options` endpoint reuses the existing eligibility/expiry/squad/tier logic at an unknown fee. It strips the placeholder zero saving and exposes the real percentage/cap terms. Display-only percentage metadata is excluded from the financial claim plan. The read does not reserve or spend anything. The existing checkout still validates ownership, availability and exact terms before payment. Invalid or failed discovery has a Retry state; a missing location is no longer presented as a requirement for viewing rewards. Expired saved selections remain clearable.

One discovery request is shared across both reward types; opening/closing the dialog and changing location do not refetch it. User/campus/squad changes invalidate its state and ignore earlier responses. Quotes remain authoritative and can replace the discovery list with order-specific choices. No database migration, new environment variable or recurring task is required. No admin page-by-page work is included; that belongs to the other auditor.
