## 4. Auth-related calls (flagged)

Token transport: `Authorization: Bearer <access_token>` + optional `X-Campus-ID` (apiClient.js builds these).
Token storage: `hg_access_token` / `hg_refresh_token` in localStorage ("remember me") or sessionStorage; `hg_remember` flag selects the store.
Refresh: single automatic retry on 401 (`options._retried`), refresh via `POST /auth/refresh { refresh_token }`; tokens are **not** cleared on transient failures — only a definitive 401/403 surfaces a retryable error.

Backend auth enforcement (verified by reading the code):
- `app/middleware/auth.py:107-112` — rejects anything that is not `Authorization: Bearer <jwt>` with 401 `SESSION_MALFORMED`.
- `app/middleware/auth.py:26,152,155` — 401 when Supabase rejects the token/profile, 403 `ACCOUNT_DEACTIVATED` when the profile is deactivated.
- Frontend error surface: `ApiError` reads `data?.error || data?.message` (apiClient.js:161) which matches the backend's `{"error": ...}` envelope produced by `abort(401, MSG…)`.
- `X-Campus-ID` is accepted by CORS (`allow_headers=[… "X-Campus-ID" …]`, `app/__init__.py`).
