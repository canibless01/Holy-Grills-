# Admin commerce loading — 25 November 2026

Orders now receives customer name/phone alongside each authorized order, using the existing `orders_user_id_fkey` relation. It no longer downloads a separate limited user list to discover names. The order-specific contact number takes precedence over the account phone. Server-side order-ID prefix search is debounced; changing filters invalidates older responses immediately. Page reads are bounded to 50 rows plus one lookahead, with previous/next controls rather than fetching the full order history or running a separate exact-count query. Load failures show an explicit retry and suppress stale order actions/totals. Existing role/campus/payment/test-order boundaries remain authoritative.

Analytics separates its four headline reads from tab-specific detail reports. Retention, referrals, gifts and brand requests wait until the customer tab is opened. Items, marketplace and cart details load for the sales tab; operations retains its own report components. A slow auxiliary report cannot hold the headline overview behind the original all-report spinner. Each group has visible loading/error/retry behavior and version guards against late range/tab responses. No persistent cache was added for financial or permission data.

Native Chromium at 393px and 1280px covers pagination, one debounced final query, late-search suppression, failed-load recovery, zero all-user-list requests, and rendering headline revenue while a hidden/auxiliary read is held. Existing analytics date/race/export/retry tests pass with brand requests deliberately deferred until their tab opens. Frontend typecheck, ESLint, message validation and the complete production build passed. These checks prove request behavior under controlled transport; no claim is made about a fixed number of seconds on every production device/network.
